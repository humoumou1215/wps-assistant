# 报告模板的数据绑定

用于将源数据映射到既定报告模板。读取本节及任务匹配的图表、动态目标或 PPT 续表分支；规则组织遵循 SKILL.md，生命周期与交付遵循系统提示词。

## 映射：每个目标都有依据

一次读取源表名称、表头、边界与样本，目标页标题、相关文本、表格表头、图表类型及对象 ID。结合用户说明和字段语义，逐项确定“源字段 → 筛选/计算 → 目标”。相同数值不能证明关联；模板旧值提示样式及用途，不是新数据。完成标准是每个要求更新的目标均有来源或明确保留原因。

- 报告期从源数据确定；最新月份标准化后比较，不依赖行顺序或电脑当前月。封面、指标、环比、事件列表、图表窗口和下月计划使用同一报告期。
- 区分口径：汇总指标和明细统计可能覆盖不同总体，分别取值并检查目标标签。按期率写清分子、分母和是否只统计已完成记录。
- 表头定位列，业务 ID/名称识别记录；明确空行、合计行、历史月份是否排除。状态/日期冲突按已确定的业务口径处理；零分母返回空值/提示。
- 金额单位、比例与百分点分别处理：0.941 展示 94.1%，比例差 ×100 是百分点。Excel 日期可能为序列数或文本，先判断类型。
- 事实通过工具查，取舍才问用户。同名字段、口径冲突或展示容量确实要求取舍时，集中询问最少问题；有明确证据的映射直接执行，简述关键假设。

## 重算：数据变化无需重建

Transform 每次读取当前有效范围：`UsedRange` 是候选边界，可能含残留格式，按关键列非空过滤，不硬编码首次末行。新增列按表头映射，有明确目标用途的字段才纳入展示；未知字段可保留在具名明细中，不自动塞进每个模板表格。列增减由展示映射决定，源列移动不改变字段含义。

各业务变量使用同一报告期口径，保留原始业务值及可核对汇总。只读排序可用 `reduce` 将新项插入新数组，避开守卫禁用的 `sort`；标准化年月字符串可直接比较。


## 重写：在模板内更新

- **文本**：更新现有文本框/单元格；局部选区只改对应字符。保留字体、字号、颜色、段落、位置尺寸；混合格式按区段更新或保存恢复对应样式。固定标题、Logo、背景和装饰不参与绑定。
- **表格**：先读取实际表头、行列数、位置尺寸、行高列宽、表头/正文样式和相邻边界。按“表头 + 明细”调整行数，减行时删除/清空过期行；已映射字段变化时按表头映射调整列，不固定循环旧列数。写方法检查及调用仅放在 Render。
- **有限执行**：增删前计算差额，用有限循环；每次操作后重新按稳定 ID 取得对象及集合读取 Count，验证恰好变化一项，否则立即报错，避免缓存的对象/计数误导后续操作。不要用依赖宿主 Count 变化的无界 while 循环。工具超时不证明宿主旧代码已停止；先核实执行状态及迟发效果，再补写，避免叠加操作。
- **原对象优先**：支持行列增删时在原表调整，让新增行列继承相邻样式。确需替换时先创建并验证新对象、复制模板样式，再移除旧表；定位逻辑使用新 ID，并按动态目标章节返回当前 targetRef。
- **容量**：维持页面安全区域，检查换行、遮挡、页脚，保持合理列宽、行高与可读字号。PPT 表格必须读取并按续表章节维护续表；其他展示超容量时按任务要求用模板续页/分表，确需取舍才询问。不要静默截断明细、无限缩字或覆盖页脚。
- **幂等**：同一值重写两次，对象数量、内容和布局一致。只管理绑定或自行创建的对象，不清空整页。

## 验收

先验证重算值：报告期、行数、关键记录、汇总和单位。再验证重写：所有映射目标读回正确，表格行列数、图表类别/值与预期一致，未绑定对象及关键样式保持。只查询验收所需字段。

源数据变化后对原规则重算重写，分别检查数值变化、增行、减行及已映射列变化；连续重写检查无重复对象。未实际验证的分支只能说已设计支持。仅在验收授权范围内改测试数据，记录并恢复来源，再重算重写回实际数据。

## 图表

保留原生图表、配色、图例、坐标轴；更新已有系列分类与数值，核实宿主实际读取路径和单位。可能依赖内嵌工作簿，写后在独立调用重新查询类别/值；不能只改标题或画文本冒充图表更新。趋势窗口依据报告期滚动，类别与值长度一致。赋值成功却读回不变时，成员可见或属性描述符可写不证明宿主已更新。按实际系列公式/范围或可访问的工作簿确定数据源；有已知签名、现有范围和恢复依据时，可最小验证源范围方法，随后恢复并核实。工作簿为空只说明该访问路径不可用；确有新证据才验证其他入口。缺少可写路径时报告宿主 API 阻塞，避免反复猜公式、重复激活或改画其他对象。

## 动态目标的返回约定

写入前预检计划目标不超过 200 处、完整 `targetRef` 不超过 16000 字符；超限时报展示容量限制，不能先修改文档再截断定位信息。新增对象取得 ID 后、继续写入前再次核对引用长度。

完成规则内写入和回读后，返回普通 JSON 对象。例如 PPT 表格的 `currentTables` 为重新核实存在的原表及全部保留续表，使用实际稳定 ID：

```js
return {
  renderTarget: {
    targetRef: currentTables.map(table =>
      `SlideID:${table.slideId}!ShapeID:${table.shapeId}`
    ).join("+")
  },
  rowsPerPage: currentTables.map(table => table.rowCount),
  addedPages,
  removedPages
};
```

`renderTarget` 仅接受必填 `targetRef` 和可选 `description`（最多 1000 字符；省略保留，`null` 清除）。工具校验后与 `lastRun` 一起原子保存，聊天及变量页的单条/批量重写均生效。已有规则不返回此字段时不变；普通结果顶层的 `targetRef` 不会更新定义。无效元数据或写盘失败会报告本条失败并保留原目标定义，但已写文档不回滚，须先核对实际页/表格再修复规则。返回新引用不等于通过布局验收，Agent 仍需独立只读回读。既有 Render 不会因技能升级自动具备分页逻辑，用户纠正旧规则时需读取完整定义并原位更新代码。

## PPT 表格：每次重写都维护续表

首次写入和后续重写都适用；另读报告通用流程和动态目标章节。Render 必须把容量判断、分页及续页增减写入可重复执行的规则，不能只对当前数据手工补一页。默认在原表后接续表页，记录增多时按需新增一页或多页，记录减少时重新紧凑分页并回收空余续页；不等用户另提“新增一页”或“删除一页”。用户明确限定页数或禁止增删页时遵循限制，无法完整展示才询问取舍。

- **计算容量**：读取页面尺寸、表格位置/宽度、列宽、表头与正文行高，以及标题、页脚和相邻对象的边界，确定可用高度。以模板的可读字号与正文行高为基准，给换行内容留足行高，按当前单元格内容和实际排版计算每条记录需要的高度；以“重复表头高度 + 本页各行高度”是否超过安全区域决定分页，不能只按首次数据行数、固定每页条数或把表格整体压进原高度。表头、合计行及说明也占容量；单条记录在可读样式下仍放不进一页时报告该记录并询问展示方式，避免反复加空续页。
- **连续分配**：分页是 Render 的展示职责，Transform 保留完整业务记录与稳定顺序。按记录顺序连续分配到原表和续表，每页重复表头，续页标明标题及“续表”；合计/说明按其业务含义放置，不把全表合计误当每页小计。保留原表和原始页面，空数据清理旧明细及自动续页，在原表按模板表达空状态。
- **复用与新增**：每次先查找本规则已有的续页和表格，优先复用稳定 ID；不足才按已核实的模板版式新增，接在本表所属页组后，保持背景、标题、表头、列宽、字体、配色和页脚，不复制其他业务表格、旧明细或图表到续页。原表与其自动续表属于必须联动的一个目标组，可由同一 Render 管理；无关表格和业务页仍分别绑定。
- **持久归属**：只写原表且无需续页时，不要求创建归属标记；需要新增或回收时，先验证持久归属与宿主写入路径。每条 Render 自行重新发现续页。新增前验证可跨次执行读写的页/对象归属标记（例如当前宿主支持的 Tags），关联变量 ID、原始页/表格的稳定 ID 和续页顺序。页码、标题或名称相同不能证明归属；仅靠本次局部数组或上次固定页码无法支持下次回收。每次重新发现并核对标记和 ID，重写中断后先核实已生成的页再继续；没有可验证的持久归属方式时报告阻塞，不盲目追加或按名称删除。
- **减量回收**：先把所有保留记录写入并读回所需页面，再删除本规则自动生成且已不需要的续页，从后向前删除并逐次重新取页、核对页数变化。原始页、用户预先存在的页、其他规则生成的页不得当作多余续页删除；自动续页若已加入不属于本规则的内容，保留该页并说明不能自动回收的原因。保留的页同步清除过期行、更新续表标题，其他页面保持相对顺序。
- **布局回读**：写入后重新读取表格、行及可用文本边界，核对实际高度、文字裁切和相邻对象遮挡；超出安全区域的末尾记录移到下一续页，重新核对，修正循环必须有明确上限和进展检查。无法通过宿主读数确认文字布局时补视觉验收或说明未验证，不能只凭写入成功宣称页面正常。所有创建、标记和删除等写方法的检查及调用都在 Render 中，按当前宿主验证签名，不照历史目录猜 API。
- **定位与验收**：Render 返回原表及当前续表的稳定页/对象 ID、每页记录数和新增/回收页数；按动态目标章节通过 `renderTarget` 回传当前完整目标，剔除已删目标，由工具层保存引用。不能在 Render 内调用工具更新定义，也不依赖 Agent 在界面按钮执行后补做 update。全页组记录总数与业务 ID/内容顺序必须和 Transform 一致，无遗漏、重复或过期记录。验证“单页 → 多页 → 页数减少 → 单页/空数据”和同值连续重写，检查页数、表格数、内容及布局稳定；仅设计了这些分支时不得声称已实测通过。

Agent 怎么会写 WPS API？

外部 Agent 可加载 Skill / Reference；内嵌助手使用系统提示和十个工具的描述约束代码生成。

Skill / Reference

这是 Agent 的“WPS API 说明书”

里面告诉 Agent：WPS JS API 有哪些对象、怎么读工作簿/幻灯片/图表、常见代码怎么写，以及哪些操作必须放进 Render。

1先核实文档与 API
通过工具取得文档和位置；外部 Agent 可按需查阅 Skill / Reference。
2Agent 自己生成 JavaScript
return Application.Workbooks.Item("预算.xlsx").Name;
3代码交给 wps-mcp
查询代码 → wps_run_readonly_code　　提取代码 → Transform　　写入代码 → Render
4Add-in 在 WPS 里执行
MCP 不把它翻译成另一套“自创 WPS API”。
所以项目能保持简单： WPS 已经有一套很大的 API。我们只需要教 Agent 会用它，而不是复制它。

两条护栏，就够了

不是把 WPS API 包得很厚，而是只把“读”和“写”的边界说清楚。

想看，可以直接看

Agent 生成只读的 WPS JS API 代码，通过 wps_run_readonly_code 查询表格、幻灯片、选区、图表或文字文档。先核实文档与具体位置，再执行查询。

wps_list_documents → wps_get_document → wps_run_readonly_code

想改，必须走 Render

Agent 也直接写 WPS JS API，但所有会修改文档的代码必须成为 Render，再由正式执行入口运行。前置条件是 Variable 已经跑过一次 Transform、手里有值。这样写能力强，边界仍然简单。

wps_create_variable → wps_run_transform
wps_create_render → wps_run_render → WPS
被拦下来的时候，一次说清

判据集中在 src/readonly-guard.ts，违规一次性全部报出，每条带行列号、源码行和改写建议 —— 拿到就能一轮改完，不用“报一条、改一条、再报一条”。

你写的为什么被拦
o.a = 1任何成员赋值都拦。判据是纯语法的，不区分文档对象和你自己声明的本地对象。
i++ · --i自增自减一律拦，本地循环计数器也不例外。写成 i = i + 1 就通过了。
new Date()所有 new 都拦，内置构造器（Date / Map / Set / RegExp）一样在内。
arr.sort()方法黑名单按属性名匹配：读一下就拦，本地数组也中招。换个属性名，或者挪进 Render。
记住这个方向： 上面这些写法在 Render 里全部合法 —— Render 的代码根本不经过这道守卫。所以“想改文档”不要跟守卫较劲，直接写成 Render。
内嵌助手的修复额度：每个聊天轮次最多消耗 3 次守卫违规额度，按模型轮次计数；同一模型轮次的多个违规调用只算一次，用尽后中断。外部 MCP 调用不施加这份 Agent 额度。
执行边界：Acorn 静态检查属于 best-effort，不是 JavaScript 沙箱；只运行可信代码。Render 是正式修改入口，用户已请求的写入在核实目标后执行。多条 Render 分别报告结果，部分失败和停止生成都不会自动回滚已完成的修改。

怎么把它接上？

先完全退出 WPS，构建并安装本机服务与 Add-in，再启动 WPS、确认连接。要求 Node.js ≥ 22.19.0。

Step 1 · 构建项目

只监听本机

一个进程提供面板 API、HTTP MCP、Add-in 资源和 WebSocket，默认端口 18766，只绑定 127.0.0.1；默认还连接 stdio MCP。

npm ci
npm run build
Step 2 · 注册 Add-in

写进 publish.xml

Windows 注册 ET / WPP / WPS 条目并启动服务。macOS 安装常驻服务与专用 Add-in，补齐 Writer 启用记录。完成后重新启动 WPS。

Windows PowerShell:
node scripts/install-addin.mjs
$env:WPS_MCP_TRANSPORT = "http"
npm start

macOS:
scripts/install-macos-service.sh
scripts/install-macos-addin.sh
Step 3 · 选择入口

面板或客户端

WPS 中打开「助手面板」并配置模型；外部客户端选择 Streamable HTTP，填写本机 MCP 地址。两种方式都需要 Add-in 在线。

WPS MCP → 助手面板
外部客户端: http://127.0.0.1:18766/mcp
Step 4 · 验证

先问服务，再看文档

健康检查通了、WPS 里能列出 documentId，才算接通。注意：注册后必须完全退出并重启 WPS（托盘图标也要退）。

curl http://127.0.0.1:18766/health
具体命令与平台限制见 README。Windows Writer 仅通过 publish.xml 加载的兼容性尚未实测。更新代码后运行 npm run build 并重启桥接，再重新加载面板。Windows 可用 scripts/restart-local-bridge.ps1 检查空闲状态、保留数据并重启。

出了问题，从日志找起

默认有文件日志和 stderr 输出。MCP 的 stdout 只传协议消息。

JSON Lines · 默认 info

沿一次操作往下查

记录启动与退出、连接、配置、HTTP、聊天、模型用量、工具及 WPS RPC 的状态、耗时和错误码。HTTP 响应提供 x-request-id。

requestId→turnId→toolCallId→rpcId
外部 MCP 调用没有聊天 turnId；stdio 调用没有 HTTP requestId。正常 GET 与静态资源在 debug 级别记录。
10 MiB × 5 份

记录有限，内容克制

默认每份日志 10 MiB，保留当前文件与 4 份归档，自动删除最旧归档。记录操作元信息，省去聊天正文、文档内容、代码、请求头和工具结果；凭据统一脱敏。

<数据目录>/logs/wps-mcp.log
wps-mcp.log.1 → .4
文件写入失败时继续输出 stderr；队列最多 1000 条，满时丢弃新增文件副本。正常信号或致命异常退出前最多等待 2 秒落盘。
按需要调节日志

环境变量在服务启动时读取，修改后重启生效。

环境变量默认用途
WPS_MCP_LOG_LEVELinfodebug / info / warn / error / silent
WPS_MCP_LOG_DIR数据目录/logs自定义日志目录
WPS_MCP_LOG_FILE1设为 0，只保留 stderr
WPS_MCP_LOG_MAX_BYTES10485760单文件上限，最小 1 KiB
WPS_MCP_LOG_MAX_FILES5包含当前文件，最多 100 份
Windows: %APPDATA%\wps-mcp\logs\wps-mcp.log
macOS: ~/Library/Application Support/wps-mcp/logs/wps-mcp.log
两类记录各有用途：logs/ 用于运行排障；pi/sessions/ 用于恢复会话，可能包含工具结果和文档数据，独立于日志脱敏与轮转。强制结束进程不能保证尚未落盘的日志被保存。

职责分布：谁拥有哪件事？

边界越清楚，项目越不容易从“小桥”长成“大平台”。

Agent

内嵌或外部 Agent 理解自然语言和引用，直接生成 WPS JS API 查询、Transform 与 Render 代码。

拥有：意图理解与规则生成；按已保存规则运行的重算、重写无需模型。

MCP Server

暴露少量工具、登记文档、保存 Agent 写好的代码规则、按 documentId 找到正确的 Add-in。

拥有：Variable / Transform / Render 的定义与执行入口。

WPS Add-in

待在真实 WPS 进程里，接收执行请求，直接运行 Agent 生成的 WPS JS API 代码。

不负责：理解用户意图，也不自己发明 Transform / Render。

WPS

真正拥有工作簿、幻灯片、选区、图表、样式和当前编辑状态。

事实来源：文档内容以 WPS 当前状态为准。

建立绑定：只需要走完这 8 步

先学会 API、再看清文档；随后定义 Transform / Variable / Render，最后执行写入。

1

收到任务

自然语言 + @当前选区 / 文件引用交给 Agent。

2

核实约束

内嵌助手按提示与工具约束执行；外部 Agent 可查阅 SKILL.md / Reference。

3

找到文档

wps_list_documents
wps_get_document

4

写代码调查

Agent 直接生成只读 WPS JS API 代码，交给 wps_run_readonly_code 执行。

5

写 Transform

Agent 生成提取数据的 WPS JS API 代码，wps_create_variable 保存它（同时建出 Variable）。

6

得到 Variable

wps_run_transform
运行 Transform，产生最新值。

7

写 Render

Agent 生成修改目标文档的 WPS JS API 代码，wps_create_render 保存它。

8

真正写入

wps_run_render
Add-in 在目标 WPS 文档执行 Render 代码。

绑定建好以后：在变量面板显式点击重算、重写，程序直接跑 Transform → 更新 Variable → 跑 Render，无需再次请求模型。重算和重写是两个操作；当前没有文件变化监听或定时同步。

开发时守住三个边界

复用 WPS API、保持查询只读、直接执行已保存规则。

不要复制 WPS API

不要为每个 WPS JS API 再包一层 MCP Tool。Skill / Reference 负责“教”，Agent 负责直接生成 WPS JS API 代码。

不要让查询偷偷写

wps_run_readonly_code 和 Transform 都应该是只读。文档修改只有 Render 一个正式入口。

规则运行直接执行

Agent 可以内嵌在服务中，但已保存规则的重算、重写直接由工具执行，保持行为可检查、可重复。

Simple means powerful.

让 AI 找到文档，保存规则，再把结果写对位置。
内置助手、外部 MCP、同一套工具；Transform / Variable / Render 把一次任务变成可重复执行的绑定。

不复制整套 WPS API 不发明新的复杂 DSL 不让 Agent 参与日常计算 不把桥变成大脑

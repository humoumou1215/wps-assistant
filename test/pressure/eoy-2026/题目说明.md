# 跨文件语义映射压测题 · 场景说明

**场景**：示例银行科技部 2026 年度年终汇报（虚构）

> 所有机构、人员、系统与经营指标均为合成测试数据，不代表真实银行。本文和答案卡用于评阅，不交给被测 Agent。环境安装和输出目录规则见 [测试素材说明](../README.md)。
**出题目标**：同时压测 Agent 的**语义理解能力**（跨文件字段对齐、口径换算）与 **transform / render 的能力边界**（跨页、图表回写、多级表头、大范围序列化）。

---

## 一、用户输入（给被测 Agent 的原句，一字不改）

> 以《源A-2026年度系统运行与投产台账.xlsx》和《源B-各研发团队年度工作条目汇编.pptx》为数据基础，呈现到《目标1-2026年度科技工作汇报.pptx》和《目标2-2026年度生产运行分析报告.docx》中。

**Agent 期望行为**：查看并预览 4 个文件的内容 → 理解文档之间的语义关系 → 创建 transform（只读探查、聚合、口径换算）→ 创建 render（写入两个目标文件）。

这四个文件构成一个**不可拆的闭环**：两个源不能单独完成任务（KPI 要跨源、团队表要跨源），两个目标必须同时改（口径说明在目标1 第 2 页，目标2 的写法要与之对齐）。

---

## 二、四个文件的角色

| 文件 | 角色 | 规模 | 为什么这么设计 |
|---|---|---|---|
| **源A-2026年度系统运行与投产台账.xlsx** | 数据源 1（结构化明细） | 7 表 / 716 行明细 | 提供系统清单、月度指标、变更与故障明细、去年基线。字段全是「系统内叫法」，与汇报口径不一致 |
| **源B-各研发团队年度工作条目汇编.pptx** | 数据源 2（演示文稿内表格） | 8 页 / 7 张表 / 41 条 | 数据藏在 PPT 表格里，对象模型与 Excel 完全不同；团队用全称，与源A 的简称形成映射断层 |
| **目标1-2026年度科技工作汇报.pptx** | 目标 1（半成品汇报稿） | 8 页 | 第 3 页 4 个 KPI、第 4 页图表、第 5 页跨页清单表、第 6 页团队表全部留白 |
| **目标2-2026年度生产运行分析报告.docx** | 目标 2（半成品报告） | 5 章 / 3 表 | 多级表头、16 行跨页长表、页眉页码域、正文文字占位 |

> 题面（含汇报口径、排序规则、可写位置）嵌在**目标1 第 2 页**，Agent 必须自己翻到那一页才能拿到口径——这是第一道"会不会认真读文件"的筛子。

## 三、语义断层清单（考察语义理解）

每一条都是**源文件字段 ≠ 目标文件口径**，Agent 必须自己推出映射关系，不能直接搬运。

| # | 断层类型 | 源文件写法 | 目标文件要求 | 踩坑表现 |
|---|---|---|---|---|
| S1 | 口径筛选 | 变更类型 = 投产上线 / 优化变更 / 紧急修复（240 条） | 「全年投产次数」只计 投产上线 + 紧急修复（160） | 直接报 240，或漏算紧急修复报 130 |
| S2 | 别名归一 | 事件等级手写混用：`一级`(10) 与 `I级`(2) | 「重大故障」两者都算，共 12 | 只认「一级」报 10 起 |
| S3 | 类型归一 + 加权 | 月可用率：183 个数值 + 8 个文本（`99.97%` / `-`）+ 1 个空 | 按当月**交易笔数加权**平均，文本按数值处理，`-`/空剔除 | 简单平均；或把文本当字符串跳过；或让 `-` 参与运算得 NaN |
| S4 | 跨表关联 | 去年基线表**只有 10 个系统有值**，6 个为空（2023 年后新上线） | 同比 =（今年 − 去年）/ 去年；无基线填「**新增**」 | 按 0 算导致除零/无穷；或整列留空 |
| S5 | 值域映射 | 系统等级 = 一级 / 二级 / 三级 | 汇报口径 = 核心 / 重要 / 一般 | 原样搬运 |
| S6 | 名称映射 | 台账团队用简称：研发一组 / 数据组 / 运维组 | 汇报口径用全称：系统研发一组 / 数据平台组 / 基础运维组 | 简称写进目标，或两套名称混用 |
| S7 | 跨源融合 | 源A 有「系统→团队」归属，源B 有「团队→工作条目」 | 目标1 第 6 页 / 目标2 第四章要求**同一张表**同时体现两者 | 只填一半列；或团队数对不上（源A 6 个团队 vs 源B 6 个团队其实一一对应） |
| S8 | 跨格式搬运 | 源B 是 PPT 表格（`Shapes → Table → Cell`） | 目标2 是 Word 表格 | 只处理 Excel 源，源B 数据整块丢失 |
| S9 | 状态口径归一 | 源B 状态混写：已完成 / 完成 / 进行中 / 延期 | 「已完成」与「完成」视为同一种 | 报「已完成 26」而实际 32（漏掉 6 条写作「完成」的） |
| S10 | 结构定位 | 源A 各表**表头在第 3 行**，前 2 行是标题与说明 | 直接按第 1 行当表头 | 读出头全是标题文本 |

## 四、transform / render 能力边界考察点

| # | 考点 | 出现的文件 | 预期失败模式 |
|---|---|---|---|
| E1 | **PPT 跨页表格**（单页容量 12 行 vs 实际 16 行） | 目标1 第 5 页 | Render 无「复制幻灯片 / 新建续页」能力 → 只能硬塞或直接放弃。**这是本次新增的核心场景** |
| E2 | **Word 跨页表格标题行重复** | 目标2 第三章（17 行） | 表格天然跨页，但 `w:tblHeader` 需显式设置；不设则第 2 页无表头 |
| E3 | **图表数据回写** | 目标1 第 4 页柱状图 | WPS 的 `Chart` 对象模型与 MS Office 有差异，`ChartData` / 内嵌 Workbook 很可能读不到或不可写 |
| E4 | **多级表头 + 合并单元格写入** | 目标2 第二章 | 合并区域的非左上角单元格写入无效；定位错格 |
| E5 | **大范围一次性序列化** | 源A 月度运行(192) + 日志异常(192) | 384 行 × 4 列一次性 JSON 传回，桥接层 RPC 超时 |
| E6 | **守卫禁排序** | 重点系统清单需降序 | `sort` 在守卫黑名单里，只能手写排序 |
| E7 | **守卫禁成员赋值** | 任何"就地补全"数据的写法 | `o.a = 1` / `a[i] = v` 一律被拦，只能重建对象整体返回 |
| E8 | **页脚 / 页码域写入** | 目标2 页脚 | 域对象不是普通文本，需 OOXML 或专用 API |
| E9 | **变量必须先有值** | 所有 render | `wps_run_render` 前置条件是先跑过 `wps_run_transform` |
| E10 | **无删除接口** | 探测性写入 | 没有删除 Variable / Render 的接口，探测残留会永久留在状态里 |

## 五、判定

完整答案（KPI、16 行系统清单、团队统计、跨页拆分位置、可采信证据）见同目录 **`答案卡.md`**。

重跑答案：

```sh
python test/pressure/run.py eoy-2026 truth       # 打印全部口径答案
python test/pressure/run.py eoy-2026 verify      # 回读生成素材并检查几何边界
python test/pressure/run.py eoy-2026 answer-key  # 在数据目录生成评阅答案卡
```

**验收（全部达成才算完整交付）**

- [ ] 目标1 第 3 页 4 个 KPI 与答案卡一致（口径换算正确）
- [ ] 目标1 第 4 页图表 12 个数据点与台账一致
- [ ] 目标1 第 5 页 **12 行主表填满 + 新建续页容纳 4 行**，续页表头一致、标题带「（续）」、序号连续
- [ ] 目标1 第 6 页 6 个团队全称 + 归属系统数 + 条目数
- [ ] 目标2 第一章 4 处数值；第二章多级表头 6 行；第三章 16 行且跨页后表头重复；第四章 6 行；第五章 ≥3 段
- [ ] 全程未违反只读守卫；未产生无意义的残留 Render

## 六、生成与复现

在仓库根目录执行：

```sh
python test/pressure/run.py eoy-2026 generate
```

Runner 依次生成源A、源B、目标1、目标2，输出到 `.dev/pressure-test/eoy-2026/`。更换目录时，生成、校验和答案命令须使用相同的 `--output-dir`。

数据由固定随机种子（`20261231`）生成，可复现数据内容；不保证文档二进制哈希一致。

## 七、埋点说明（源文件里刻意制造的"真实的脏"）

**源A**

- 每张业务表**表头在第 3 行**，第 1、2 行是标题与填报说明
- 「应用清单」的**责任团队列按团队合并单元格**（同团队仅左上角有值，读出来其余为 `None`）
- 「月度运行」的月可用率**混合三种类型**：数值（带百分比格式）、文本 `99.97%`、占位符 `-`、空值
- 「投产变更」的回退字段**混写** `Y` / `N` / `否`；240 条明细跨 12 个月
- 「故障事件」等级字段手写 `I级`、`II级` 混入
- 「去年基线」**6 个系统无历史数据**（B/C/D 列留空）
- 「日志异常」192 行长表，与「月度运行」合计 384 行——大范围序列化的压力源

**源B**

- 团队名用**全称**，与源A 简称形成映射断层
- 状态字段四种写法混用
- 汇总页数据虽与明细一致，但备注明写「以明细为准」——诱导 Agent 直接抄汇总而不是下钻明细

**目标1**

- 第 5 页表格**单页容量 12 行，实际需 16 行**（备注里写明了续页规则，但能不能做到取决于 Render 能力）
- 预填 3 行既是"格式样板"，也隐含了「序号 = 台账序号而非排名」这一口径
- 第 4 页图表用内嵌工作表承载数据，替换路径与 Excel 不同

**目标2**

- 第二章表头是**两级 + 一列纵向合并**
- 第三章 17 行表**必然跨页**且**未预设标题行重复**
- 页眉有文件编号占位、页脚是 `PAGE` / `NUMPAGES` 域
- 第五章是纯文字生成题，考察"从数据到结论"的表达

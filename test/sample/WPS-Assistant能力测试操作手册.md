# WPS Assistant 能力测试操作手册

项目交付台账 / 周报 / 周会

**重要：本手册是评测侧材料。测试时不要把本手册交给 Agent，也不要在 WPS 中保持本手册打开。被测 Agent 只应看到工作中的 Excel、Word、PPT 三个业务文件。**

## 1. 配套文件

| 文件 | 用途 |
| --- | --- |
| 项目交付台账-第1轮.xlsx | 初始工作文件；第一次建立变量、Transform 和 Render |
| 项目交付台账-第2轮.xlsx | 第二轮业务数据；用于验证重新计算后变量变化、重新写入后目标更新 |
| 项目交付台账-第3轮.xlsx | 内容与第2轮故意完全相同；用于验证重复执行的幂等性 |
| 项目交付台账-第4轮.xlsx | 第四轮业务数据；风险项目数量再次增加 |
| 项目交付周报-测试版.docx | Word 目标文件 |
| 项目交付周会-测试版.pptx | PPT 目标文件 |

Excel 的 4 个轮次文件都具有相同的工作表结构：项目跟进、风险跟踪、里程碑、上周快照、人员投入。测试过程中应始终保留“第1轮”文件作为实际工作文件；后续轮次文件只作为数据来源。

## 2. 第一轮：建立绑定

建议给 Agent 的用户请求：

> 请根据当前的项目交付台账更新项目交付周报和项目交付周会。周报和周会中已有的项目进展、本周变化、重点项目跟踪/重点关注、下周安排和资源协调都需要按最新数据更新。重点关注只保留中高风险且未关闭的项目。后续我还会继续维护这份台账，请把需要持续更新的数据关系做成可以重复重算和重写的变量及绑定。

第一轮应观察以下业务结果（不要把这些内容告诉 Agent）：

- 风险跟踪中“经营数据集市”有两条风险记录，项目主表只有一条项目记录；结果应能把项目属性和多条风险合并，而不是生成两个重复项目。
- 项目跟进页的“当前阶段 / 下一节点 / 计划日期”应结合里程碑信息更新，而不是只复制项目主表中的“状态”。
- “本周变化”应比较上周快照与当前项目明细，识别状态、计划日期、当前进展以及新增项目的变化。
- “资源协调”应能发现同一人员跨多个项目的投入关系，并做汇总或管理层摘要。
## 3. 多轮数据更新方法

不要用第2/3/4轮文件替换正在测试的第1轮工作簿。绑定依赖同一个源文档。后续轮次只把数据复制到第1轮工作簿的对应工作表中。若使用 WPS 打开轮次文件复制数据，复制完成后先关闭轮次文件，再让 Agent 或变量面板执行重算/重写，避免同时出现多个同名数据源。

| 轮次 | 需要更新的工作表 | 操作 |
| --- | --- | --- |
| 第1轮 | 全部 | 直接使用第1轮 Excel 建立绑定并完成第一次重算、重写 |
| 第2轮 | 项目跟进、风险跟踪、里程碑 | 把第2轮数据复制到正在测试的第1轮工作簿，然后只执行已有规则 |
| 第3轮 | 无需更新（与第2轮完全相同） | 不改任何源数据，连续执行重算→重写两次 |
| 第4轮 | 项目跟进、风险跟踪、里程碑 | 把第4轮数据复制到正在测试的第1轮工作簿，然后执行已有规则 |

## 4. 复制粘贴范围

建议使用“粘贴为值”。为了避免上一轮多出来的行残留，每次先清空目标数据区域，再粘贴本轮内容。

| 工作表 | 清理区域 | 复制区域 |
| --- | --- | --- |
| 项目跟进 | A13:G21 | 对应轮次文件 A13:G21 |
| 风险跟踪 | A4:G20 | 第2轮 A4:G8；第4轮 A4:G9 |
| 里程碑 | A4:F20 | 对应轮次文件 A4:F15 |
| 上周快照 | 不变 | 不用复制 |
| 人员投入 | 不变 | 不用复制 |

## 5. 第2轮：验证“重算”和“重写”分离

完成第2轮数据粘贴后：

1. 先只执行“重算”。检查变量当前值已经变化；此时 Word/PPT 应仍保持第一轮写入结果。
1. 再执行“重写”。Word/PPT 才应更新为第二轮结果。
1. 重点关注项目的业务集合应从第一轮的 3 个项目（经营数据集市、供应链协同、合同审批）缩减为 1 个项目（经营数据集市）。
1. 经营数据集市有两条未关闭的中风险事项，但目标“重点项目跟踪/重点关注”不应因为两条风险而残留两份相同项目；具体呈现可以是一条项目下包含两条事项。
## 6. 第3轮：验证重复执行幂等

第3轮 Excel 与第2轮故意完全一致。不要修改工作文件，直接连续执行：

重算 → 重写 → 重算 → 重写

执行完成后应满足：

- Word 不新增重复段落、重复表格行或重复标题。
- PPT 不新增重复文本框、重复项目行或重复卡片。
- 已经被清掉的供应链协同、合同审批重点关注内容不能重新出现。
- 字体、颜色、边框、表格高度等不应因为重复执行持续漂移。
## 7. 第4轮：验证目标集合再次扩大

粘贴第4轮数据后执行已有的重算和重写。此轮在保留经营数据集市的同时，消息中心风险上调为中风险，并新增客户工作台中风险事项。

重点关注业务集合应从第3轮的 1 个项目重新扩大到 3 个项目：

- 经营数据集市
- 消息中心
- 客户工作台
## 8. 场景 5 的核心验收

重点不是 Agent 能否再次生成代码，而是第一次建立的绑定能否长期复用。从第2轮开始，不应要求 Agent 重建 Variable、Transform 或 Render；只运行保存下来的规则。

| 检查项 | 通过表现 |
| --- | --- |
| Transform | 每次重算都重新读取当前 Excel，并覆盖变量当前值 |
| Render 数据来源 | Render 每次从最新 variable.value 读取数据，而不是把第一轮业务值写死在代码中 |
| 覆盖语义 | 目标数据由 3 条变 1 条时，旧的 2 条能被清理；由 1 条变 3 条时能正常扩展 |
| 幂等性 | 同样的数据连续重写，文档最终状态不变 |
| 绑定生命周期 | 第2～4轮不需要重新让 Agent 创建绑定 |
